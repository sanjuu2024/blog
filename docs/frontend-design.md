# 前端设计约定

## 1. 主题模式

前端提供三种主题模式：

- `system`：跟随系统，默认模式
- `light`：浅色模式
- `dark`：深色模式

`system` 只是用户选择的模式，页面实际渲染时会解析为 `light` 或 `dark`。

用户头像通过 `AppUserAvatar` 统一展示：传入头像图片、游客或已注销用户时背景使用 `--app-bg`；
普通用户没有头像图片时，使用用户 ID 或名字哈希生成背景色。

`AppUserAvatar` 通过 `isAdmin` 展示管理员徽章，调用处使用头像所属用户的当前 `role` 判断；游客和已注销账号不显示徽章，不以当前登录者角色或昵称判断他人身份。

## 2. Logo 使用

网站 favicon 与页面 Logo 使用同一个 Seedling SVG 资源，统一通过 `AppLogo` 组件在页面中展示。

- favicon、窄屏导航、后台侧边栏折叠态可以只显示图标。
- 首页、登录注册页、常规导航栏优先使用“图标 + 网站名”的组合 Logo。
- `AppLogo` 的视觉文字使用 `src/assets/svg/logo-text.svg`，无障碍名称读取 `VITE_APP_TITLE`，未配置时为 `Sanjuu Blog`。
- 文字 Logo 通过 CSS mask 渲染，默认使用 `--app-text`，可通过组件 `textColor` 属性显式覆盖颜色。
- 后续如需调整视觉文字，优先替换 `logo-text.svg`；如只调整屏幕阅读器读取的站点名称，优先通过 `VITE_APP_TITLE` 配置。
- 文字 Logo 可使用 Google Fonts 的 Long Cang 字体；该字体使用 SIL Open Font License 1.1，第三方资源声明见 [third-party-notices.md](./third-party-notices.md)。

## 3. 按钮交互

网站整体走简洁风格，基础按钮只维护一组主按钮颜色。

按钮颜色约定：

- 默认状态使用稍亮、稍柔和的主色
- hover 状态使用更深的主色
- active 状态与 hover 状态保持一致
- hover 与 active 状态下文字不加粗，只改变颜色

自定义按钮与 Element Plus 主按钮必须共享同一组颜色变量：

- `--app-button-bg` 对应 `--el-color-primary`
- `--app-button-hover` 对应 `--el-color-primary-light-3`
- `--app-button-active` 对应 `--el-color-primary-dark-2`
- `--app-button-text` 对应按钮文字颜色

Element Plus 的 `success`、`warning`、`danger`、`info` 按钮也遵循同样的交互方向：默认色稍亮，hover 与 active 使用更深的同色系颜色。后台管理页面可以在后续按业务语义继续细化这些状态色的具体取值。

## 4. 环境变量

前端环境变量按 Vite 约定管理，只有 `VITE_` 前缀的变量会暴露给前端运行时代码。

仓库可以提交不同环境的非敏感默认配置，例如：

- `.env.development`
- `.env.test`
- `.env.production`

这些文件只存放可公开的环境差异配置，例如 API 基础路径、开发代理目标地址等。生产密钥、私有 Token、云服务密钥等敏感值不能提交到仓库。

本机私有覆盖配置统一放在 `.env.local` 或 `.env.[mode].local` 中，并保持忽略状态。例如：

- `.env.development.local`
- `.env.production.local`

如果某个环境变量未来需要承载敏感信息，提交到仓库的环境文件中只保留空值或示例占位，真实值通过本地配置、部署平台环境变量或密钥管理服务注入。

## 5. 响应式布局

- 全局移动端布局断点为 `width < 768px`；极窄屏可按内容需要使用更小断点，分类页等双栏页面可根据自身布局提前切换。
- 移动端前台导航隐藏桌面导航项，通过顶栏汉堡菜单展示全部公开导航；后台隐藏固定侧栏，通过后台顶栏汉堡菜单展示前台入口和后台导航。
- 后台移动端隐藏面包屑，改为展示当前页面图标和标题；后台主内容区允许纵向滚动，避免筛选区域挤压表格内容。
- 后台表格在移动端取消固定列，分页器使用精简布局；筛选表单根据可用宽度调整列数，不产生页面级横向溢出。
- 移动端原生 `input`、`textarea` 和 `select` 的字号不得小于 `16px`，避免 iOS Safari 聚焦输入时自动放大页面。
- 文章列表在窄屏下改为封面位于上方、文章信息位于下方的纵向布局；标签等可变长度内容允许换行。
- 个人中心顶部的个人简介默认最多展示两行，仅在真实溢出时提供展开、收起操作。
- 公开用户资料卡的简介默认最多三行，沿用个人中心的实际溢出检测与展开/收起写法；卡片高度不超过视口，展开后内部可上下滚动，关闭后恢复折叠状态。

## 6. 首页内容区

首页首屏下方的内容区按以下顺序组织：

1. 置顶文章
2. 最新文章
3. 分类归档
4. 标签云

展示约定：

- 置顶文章展示按首次发布时间倒序排列的前 `4` 篇已发布置顶文章。
- 最新文章展示按首次发布时间倒序排列的前 `4` 篇已发布文章，不排除置顶文章。
- 同一篇文章允许同时出现在置顶文章和最新文章区域。
- 分类归档展示 `4` 个一级分类卡片；卡片以一级分类为主要信息，并可简要展示其下部分二级分类。
- 分类归档复用公开分类树数据，由前端控制一级分类和二级分类的展示数量。
- 标签云使用 `vuewordcloud` 展示已启用标签及其文章数量形成的热度差异。
- 标签云仅作信息展示，不提供标签详情或按标签筛选文章的跳转入口。
- 标签颜色按名称稳定映射，避免页面刷新或重新布局时随机变化。

### 6.1 文章列表搜索与筛选状态

- 前台文章列表页的 `keyword`、`categoryId` 和 `tagIds` 条件存储在 `/articles` 路由的 query 参数中。
- 应用筛选条件时先更新 URL，再由页面监听 query 参数并通过 Axios 请求文章列表接口。
- 搜索框按回车或点击搜索按钮后更新 URL，不在用户输入过程中自动发送请求。
- 多个标签使用重复的 `tagIds` 参数，例如 `/articles?tagIds=30001&tagIds=30002`。
- 刷新页面、分享链接以及浏览器前进后退时，都应恢复 URL 中的筛选条件。
- 重置筛选条件时移除 `keyword`、`categoryId` 和 `tagIds` query 参数。
- 分类和标签使用文章列表页顶部的紧凑筛选工具栏，不再使用固定侧栏；分类使用树选择，标签使用可搜索的多选下拉，工具栏随页面内容正常滚动。
- 搜索栏使用 `position: sticky` 吸附在全局页头下方，实际滚动容器为 `.app-layout`，吸顶偏移量使用 `var(--app-header-height)`。
- 应用搜索或筛选条件后保持当前滚动位置；有关键词时在列表前展示命中总数，无结果时展示明确的空状态。
- 列表优先展示接口返回的标题高亮和摘要/正文高亮片段；未返回可选高亮字段时继续展示原始标题和摘要。
- 文章列表项在浏览数、点赞数旁展示评论图标与公开评论数，点击跳转 `/articles/{articleId}#article-comments`；窄屏统计栏允许换行，不挤压文章内容。

### 6.2 分类浏览与文章目录

- 分类页在 `width < 1024px` 时默认收起分类列表，文章列表顶部显示当前分类入口；用户可通过该入口展开分类列表，选择分类后自动返回文章列表。
- 文章目录展开时不挤压正文；点击文章正文区域可以关闭目录侧栏。
- 前台回到顶部按钮滚动实际页面容器 `.app-layout`，文章目录按钮与回到顶部按钮保持独立操作。

### 6.3 文章评论内容与回复编辑

- 顶层评论和回复正文超过六个完整文本行时默认折叠，并提供展开、收起操作；判断溢出时允许 `1px` 的浏览器取整误差。
- 切换评论正文的展开状态后，滚动位置以整条顶层评论或回复为目标，避免内容高度变化后失去当前阅读位置。
- 顶层评论和回复的回复、删除、正文展开/收起操作统一放在正文下方的操作栏中。
- 顶层评论和回复使用同一个回复编辑器组件，编辑器仍显示在当前回复目标下方。

## 7. 留言页面

- 前台路由为 `/messages`，当前右侧导航顺序为“留言、关于”。友链路由暂时保留，但功能未正式开发，不在导航中展示。
- 页面采用聊天式全高 flex 布局：页头、内部滚动留言列表、底部留言编辑区；不使用 `position: fixed` 覆盖正文。
- 游客昵称和邮箱输入位于文本框上方；留言列表使用 `AppLoadMoreTrigger`，不显示页码分页器和总数。
- 登录用户不重复填写昵称和邮箱，可勾选使用账号邮箱接收该条留言的回复通知。
- 公共页面不显示回复按钮；管理员回复在顶层留言下方缩进平铺展示。
- 留言编辑器在桌面端直接展示；在 `width < 768px` 时默认折叠为“写留言”按钮，并允许用户展开或收起。
- 留言正文超过折叠高度时，删除与展开、收起操作统一放在底部工具栏；展开状态下该工具栏吸附在留言项底部。切换展开状态后定位到整条留言开头，页面只保留留言列表滚动，避免异常换行撑开页面或形成嵌套滚动。
- 游客提交成功后清空表单并提示等待审核，不把待审核内容插入列表；登录用户把接口返回的待审核留言插入顶部。
- 拒绝状态只向本人显示处理原因，邮箱永远不出现在公共响应中。
- 留言列表为空时隐藏 `AppLoadMoreTrigger` 的“没有更多留言了”文案，只保留空状态提示。
- `/messages/unsubscribe?token=...` 只展示退订确认页，用户确认后通过 POST 接口完成退订。

## 8. 后台留言管理

- 后台路由为 `/admin/messages`，页面结构和评论管理页保持一致。
- 筛选支持留言 ID、用户 ID、游客昵称、游客邮箱、内容、状态、层级和创建时间。
- 顶层留言的回复操作使用对话框；管理员可以多次回复。批量操作只提供“批量通过”，不提供批量删除、隐藏或拒绝。

## 9. 后台操作审计日志

- 后台路由为 `/admin/audit-logs`，仅管理员可访问，使用只读分页表格。
- 筛选支持操作者 ID、资源类型、目标资源标识、操作类型、操作结果和操作时间范围。
- 表格展示操作者、目标资源、操作明细、结果、失败原因、请求路径和操作时间；长资源标识与请求路径使用省略显示，鼠标悬浮时展示完整值。
- 审计日志不提供编辑、删除或批量处理按钮；失败记录使用 `danger` 状态，成功记录使用 `success` 状态。

## 10. 认证表单与文章编辑保护

- 登录和注册页使用原生表单提交语义；点击提交按钮或在表单项中按 Enter 均执行同一提交逻辑，表单校验未通过时不发送请求。
- 后台创建或编辑文章时保存进入页面后的表单快照；内容发生变化且尚未保存时，离开当前路由前要求管理员确认。
- 后台文章分类和标签选择展示全部选项，禁用项标注“已禁用”但可选；一级分类只用于分组，不可绑定文章
- 选择禁用分类或父分类时提示“该分类或父分类已禁用，文章发布后不会在前台显示。”；选中的禁用标签标注“已禁用”并提示“该标签不会在前台显示。”，新增和编辑采用相同规则
- 文章保存成功后更新表单快照并跳转文章列表，不重复显示未保存修改确认。

## 11. P2 评论直接回复通知

- 登录用户发表评论或回复时，可自愿勾选使用账号邮箱接收当前评论的直接回复通知，不额外展示邮箱输入框。
- 订阅开关只作用于本次创建的评论；邮件退订只关闭该评论未来的直接回复通知。
- 普通用户的直接回复审核通过后才发送邮件，自己回复自己不发送。
- 留言和评论通知统一提供 `multipart/alternative` 邮件；HTML 版本使用一致的品牌标题、原内容引用块、回复内容、查看链接和退订入口。

## 12. P2 站点页面与注册

- 关于页保留 `/about` 路由和现有 `2rem` 行距；后台提供 Markdown 编辑、预览和保存，不保留固定区块
- 当前前台关于页从 `/api/v1/about` 获取并展示后端生成的 HTML，未创建时展示接口返回的“暂无内容”，加载失败可重试。
- 当前注册页提供隐私政策阅读入口，使用 `el-dialog` 展示 `/api/v1/privacy-policy` 返回的 HTML；每次打开弹窗重新请求，加载失败可重试。此阶段不增加注册必选勾选或修改注册请求字段。
- 注册表单增加邮箱验证码发送、60 秒倒计时、验证码输入和隐私政策勾选
- 验证码邮件发送失败显示通用错误，不根据响应文案推断邮箱是否已注册
- 隐私政策由前端请求 `/api/v1/privacy-policy` 后在弹窗展示，不增加独立路由；接口版本变化时清除原同意状态并要求重新确认

## 13. P2 点赞、浏览与 Dashboard

- 文章详情显示浏览数、点赞数和点赞按钮；游客与登录用户均可切换文章点赞状态
- 标题下的点赞图标和数字整体可点击，复用悬浮点赞按钮的请求、状态和计数；已点赞使用主题色，请求期间禁用统计栏点赞入口，不因点击收起文章目录
- 统计栏点赞入口请求期间保持原有颜色和光标，不显示禁止光标或变淡效果，重复请求仍由禁用状态和 composable 保护
- 前台文章正文渲染后移除 img 元素的 title，避免原生悬浮提示；alt、width、height、链接 title 和数据库正文保持原样
- 评论项显示点赞数；只有登录用户显示可操作的评论点赞按钮
- 点赞控件保持稳定尺寸和明确的已点赞状态，提交中禁用重复操作，失败时恢复原状态
- Dashboard 仅管理员可见，使用总览卡片、7/30 天分段控制、趋势图和三个文章 Top 10 列表
- Top 10 分别按浏览数、点赞数、评论数展示，不在后台文章列表重复增加统计筛选

## 14. P2 通知与邮件投递

- 登录用户头像菜单增加通知入口和未读红点
- 通知弹窗侧栏固定为“全部”“回复”“管理员消息”“公告”；评论回复和留言回复在 UI 合并为“回复”
- 支持单条已读和全部已读；切换分类不改变未读状态
- 游客可以在同一入口查看有效公开公告，但不显示未读红点、未读标签或已读操作；同一公开公告对登录用户仍生成未读状态
- 后台通知管理支持指定单个用户和全部未逻辑删除用户两种已确认范围，不提供复杂筛选器
- 公告支持草稿、发布和下线；管理员消息发送后不可通过修改正文篡改用户已经收到的内容
- 后台邮件投递页展示类型、业务关联、脱敏邮箱、状态、尝试次数、失败摘要和重试操作
- 重试按钮只对 `FAILED` 记录可用，提交中保持禁用，成功后刷新状态

## 15. P2 SEO 与安全入口

- 文章详情保持 `/articles/{articleId}`，根据规范 URL 更新 canonical 和 Open Graph
- 首屏 HTML 仅由后端注入 head 元信息，正文和布局统一由 Vue 渲染；首次启动保留服务端标签，不经历简易正文与 Vue 页面两套布局切换
- 文章页使用详情响应的 seo 同步标签，不再单独请求 SEO；其他公开页面按需请求元信息，过滤异步过期结果，离开文章后清理标签，query/hash 不影响元信息
- 开发环境由 Vite 中间件转发公开 HTML 和 sitemap/robots；HTML 返回后使用 Vite 的 transformIndexHtml 注入开发资源，API 继续使用现有代理
- 游客留言编辑器加载 Turnstile；登录用户不显示挑战控件
